# Review Service Database

## PostgreSQL setup

Create the database used by the service:

```sql
CREATE DATABASE reviews_db;
```

Then configure:

```env
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/reviews_db
JWT_SECRET_KEY=change-this-secret
PORT=8006
ENVIRONMENT=development
```

The service creates its tables automatically on FastAPI startup with SQLAlchemy `Base.metadata.create_all(...)`.

## Tables

### reviews

Stores client reviews for providers.

| Column | Type | Notes |
|---|---|---|
| id | string | UUID primary key |
| order_id | string | Unique order identifier |
| provider_id | string | Provider user id from platform |
| user_id | string | Client user id from platform |
| rating | integer | 1 to 5 |
| comment | text, nullable | Review text |
| status | enum | `pending`, `approved`, `rejected`, `flagged` |
| created_at | datetime | Created timestamp |
| updated_at | datetime | Updated timestamp |
| edited_until | datetime, nullable | 72 hour edit window |

### review_replies

Stores provider replies to reviews.

| Column | Type | Notes |
|---|---|---|
| id | string | UUID primary key |
| review_id | string | FK to `reviews.id` |
| provider_id | string | Reply author |
| text | text | Reply body |
| created_at | datetime | Created timestamp |
| updated_at | datetime | Updated timestamp |

### review_flags

Stores moderation flags.

| Column | Type | Notes |
|---|---|---|
| id | string | UUID primary key |
| review_id | string | FK to `reviews.id` |
| reason | string | Example: `low_rating`, `spam`, `offensive` |
| reporter_id | string, nullable | User or system reporter |
| status | string | Defaults to `pending` |
| admin_note | text, nullable | Moderation note |
| created_at | datetime | Created timestamp |

### notifications

Stores in-app notifications generated by review workflows.

| Column | Type | Notes |
|---|---|---|
| id | string | UUID primary key |
| user_id | string | Recipient user id |
| provider_id | string, nullable | Provider context |
| type | enum | `review_approved`, `review_flagged`, `provider_reply`, `review_reminder`, etc. |
| title | string | Notification title |
| message | text | Notification body |
| payload | json, nullable | Extra metadata |
| status | string | `unread` or `read` |
| read_at | datetime, nullable | Read timestamp |
| created_at | datetime | Created timestamp |

### review_statistics

Stores aggregate provider rating statistics.

| Column | Type | Notes |
|---|---|---|
| id | string | UUID primary key |
| provider_id | string | Unique provider user id |
| total_reviews | integer | Approved review count |
| average_rating | float | Average approved rating |
| rating_1_count | integer | Distribution bucket |
| rating_2_count | integer | Distribution bucket |
| rating_3_count | integer | Distribution bucket |
| rating_4_count | integer | Distribution bucket |
| rating_5_count | integer | Distribution bucket |
| last_updated | datetime | Last aggregation timestamp |

### review_invitations

Stores invitations sent to clients after order completion.

| Column | Type | Notes |
|---|---|---|
| id | string | UUID primary key |
| order_id | string | Unique order identifier |
| provider_id | string | Provider user id |
| user_id | string | Client user id |
| status | string | `pending`, `completed`, `expired` |
| created_at | datetime | Created timestamp |
| expires_at | datetime | Invitation expiration |
| reminder_count | integer | Future reminder counter |

## Integration

- `auth-service`: should validate JWTs in production and provide `sub`/`role`.
- `user-service`: `provider_id` and `user_id` should reference platform users.
- `messaging-service`: can share real-time notification delivery later; current review notifications are HTTP/polling.
- `verification-ai-service`: can be used later to block or flag reviews from unverified accounts if needed.

## Email status

Today, the service creates invitation and reminder notifications in the database. Real SMTP delivery is still pending and should be added through an email provider or a dedicated notification service.

## Local development

Tests use SQLite overrides. For production-like local runs, use PostgreSQL:

```powershell
Set-Item -Path Env:DATABASE_URL -Value "postgresql://postgres:postgres@localhost:5432/reviews_db"
Set-Item -Path Env:JWT_SECRET_KEY -Value "dev-secret"
py -3.10 -m uvicorn main:app --reload --host 0.0.0.0 --port 8006
```

Do not commit generated `.db` files.
